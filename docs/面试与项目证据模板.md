# 面试与项目证据模板

## 项目介绍模板

我做了一个离线优先的金融风险能力训练工作台，目标不是模拟生产系统，而是把风险管理和金融工程岗位需要的能力拆成可复核的练习。我先用合成贷款数据做 SQL 分群和 PD/LGD/EAD 预期损失，再做压力测试和客群贡献拆解；随后用 Black–Scholes 和 Monte Carlo 做数值交叉核对，并记录标准误、随机种子和模型边界。最后把输入、方法、结果、局限和下一步验证组织成项目证据包。

## 风险岗位追问

### 为什么使用 Expected Loss，而不是平均 PD？

因为 PD 只描述发生违约的概率，不能反映违约后的损失强度和暴露规模。组合层面需要按笔计算 `PD × LGD × EAD` 后汇总，才能同时体现风险概率、损失率和风险敞口。

### 压力测试中的乘数是怎么来的？

训练工作台中的乘数是可调的教学情景，不代表真实机构参数。我会说明情景假设、压力传导、PD/LGD 封顶、不同客群是否应使用不同因子，并通过敏感性分析和历史/外部验证继续检查。

### 合成数据能证明模型有效吗？

不能。合成数据只能帮助我验收代码路径、公式、数据流和边界条件。真实模型验证还需要真实样本定义、时间外验证、校准、漂移、稳定性、治理和业务阈值。

## 金工岗位追问

### Monte Carlo 和 Black–Scholes 结果不一致怎么办？

我先检查风险中性漂移、折现因子、payoff、路径数、随机种子和样本方差；再报告 Monte Carlo 标准误和置信区间，而不是只比较两个价格。工作台还显示 put-call parity residual，帮助先做基准案例验收。

### 为什么固定随机种子？

固定种子用于复现和调试，不等于证明路径独立或结果稳定。我会换种子、增加路径数并观察标准误是否大致下降，再把独立检查记录在项目证据中。

## 数据治理岗位追问

### 如何保证数据口径可追溯？

我用数据字典、字段名、样本范围、日期、来源和计算公式记录输入。对于真实数据，还需要保存来源、访问时间、披露时间和许可边界；缺失、未知单位、重复记录或未来披露不应静默补零。

## 金融科技/风险产品岗位追问

### 你的产品价值是什么？

不是让模型生成更像研究报告的文字，而是把业务问题、数据合同、风险指标、失败状态、证据账本和面试表达组织成一个可验证闭环。模型或自然语言层只能解释已有结果，不能改写金融数字或绕过风险门禁。

## 不应声称的内容

不要把合成数据写成真实客户数据；不要把单机 HTML 写成生产系统；不要把本地测试写成真实用户验证；不要把项目计算写成投资业绩、alpha、监管验证或模型正式审批；不要在没有真实协作记录时声称领导跨职能团队。
